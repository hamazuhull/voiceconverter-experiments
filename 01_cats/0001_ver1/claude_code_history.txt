  Main findings:
  - Timbre: after conversion, the outputs are about as far from the target cat
    as a real human recording is from a real cat.
  - Pitch: output pitch stays at 65–400 Hz, while the cats are at 280–1230 Hz.
    Part of this is built in: the model's pitch range (fo_range in hparams.py)
    stops at 880 Hz, so the highest cat cannot be reached at all.
  - Compared with normal VC: this is not just a bigger version of the
    male↔female change. Unseen human voices explain only part of the shortfall;
    the rest is specific to cats.
  - Speaker-embedding score: the model's own speaker encoder rates the outputs
    as fairly cat-like (cosine 0.37). The same encoder produced the
    conditioning, so I treat this as optimistic. Subexperiment 2 should check it
    with an independent classifier.

  Problems found during validation, all fixed and rerun:
  - Crash: importing the repo's preprocessing code after JAX started caused a
    segfault. vc.py (experiment_01_cat_01/01.end_to_end_feasibility/vc.py) now
    loads TensorFlow first, in the same order as infer.py.
  - Cat clip selection: ranking clips only by how much of them was voiced picked
    purrs and low-frequency noise. Selection now also requires a median pitch
    of 250–1500 Hz.
  - MFCC distance: I had wrongly scaled the MFCC distance as if it were in dB.
    It is now a plain distance in librosa's MFCC units.
  - Spectrum band: the spectrum comparison was distorted by the resampler's
    roll-off near 8 kHz, so the band is now 100 Hz–7 kHz.
  - Cat pitch: for one cat (cat05), the wide-range pitch tracker locked onto
    background noise (157 Hz instead of about 280 Hz). Cat targets now use the
    150–2000 Hz estimate, and both values are kept in metrics.csv.
  - Speaker-embedding gap: the "gap closed" for the speaker embedding was too
    noisy to use, so it was removed and only the raw cosine is reported.
  - Small fixes: two of the 8 voices were initially skipped because of a
    selection bug, the F0 plot legend overlapped a label, and one README figure
    came from an earlier run. All three are corrected.

● Both stages are broken. In normal use the wrong cat pitch is created at the F0
  generation step, and the decoder then plays it back faithfully. But the
  decoder also can't produce pitch above about 550 Hz even when given the
  correct cat F0. Everything is in 03.acoustic_similarity_f0_stage/
  (experiment_01_cat_01/03.acoustic_similarity_f0_stage/README.md).

  How I tested it: I rebuilt 16 cat clips and 16 human clips (8 jvs training
  speakers, 8 Common Voice) from their own speaker code. Input and output are
  then time-aligned, so the input's measured pitch can be compared frame by
  frame at each stage. To test the decoder alone, I fed it the true F0 directly
  in place of the model's prediction.

  1. F0 generation is where the error comes from in normal use.
  - Speaker mean μ: for cats it stays at 144–323 Hz no matter the true pitch
    (325–1237 Hz), on average 14.5 semitones too low. For jvs speakers the
    offset is −3.2 semitones, for Common Voice +1.2.
  - Not the quantizer: the continuous speaker code gives the same μ (235 Hz vs
    243 Hz). Cat embeddings sit far from every codebook entry, yet 11 of 16 cats
    are assigned codes that human speakers also use.
  - Contour: the cat's pitch movement is lost (correlation 0.04, vs 0.86 for
    jvs). The contour comes only from the content encoder, so cat pitch glides
    aren't in the content features.
  - Decoder in normal use: it follows the F0 it is given for 72 % of cat frames,
    the same as for humans. It renders the wrong human-range pitch accurately.

  2. The decoder can't render pitch above about 550 Hz.

  ┌────────────────────────┬────────────────────────────────────────────────┐
  │ cat frames, true pitch │     decoder correct when given the true F0     │
  ├────────────────────────┼────────────────────────────────────────────────┤
  │ 200–440 Hz             │ 93 %                                           │
  ├────────────────────────┼────────────────────────────────────────────────┤
  │ 440–880 Hz             │ 22 % (output falls to an unrelated 330–400 Hz) │
  ├────────────────────────┼────────────────────────────────────────────────┤
  │ above 880 Hz           │ 0 % (no voiced output at all)                  │
  └────────────────────────┴────────────────────────────────────────────────┘

  I added a pitch-sweep test (shifting human pitch up and cat pitch down) to
  check whether the cat speaker code causes this. It doesn't: both fail in the
  same band (0–1 % correct at 566–800 Hz), and cats lowered into 283–566 Hz
  render correctly (82–92 %). The ceiling matches the training data, where jvs
  speakers top out at 480 Hz. About 80 % of cat voiced frames are above 440 Hz.

  3. A third limit is waiting behind these two. The 880 Hz pitch cap in
  hparams.py (fo_range) clips nothing today, because generated F0 never gets
  near it. Once generation and the decoder are fixed, it would cut 7–10 % of cat
  frames.

  So fixing F0 generation alone would only lift pitch accuracy to the
  given-true-F0 level (38 %). The decoder also needs training data with pitch up
  to about 1.5 kHz.
