
# Experiments of human-cat voice conversion

This directory is the working root directory for the human-to-cat voice conversion (VC) experiment.

## Objectives

The goal of this project is to investigate whether AI-based VC can transform human speech into cat-like vocalizations.

The experiment consists of the following subexperiments:
1. End-to-end feasibility test: generate few samples of cat-like sounds and find acoustic distance
2. Human-vs-cat discrimination: evaluate how well synthesized cat-like sounds spoof the neural classifier that distinguishes human speech from cat vocalizations.
3. Acoustic similarity analysis: compare acoustic features between real cat sounds and synthesized cat-like sounds, focusing on fundamental frequency, aperiodic components, and other relevant spectral features. Also, we compare to the ones from the condition module.
4. Worst-case analysis: identify which human voices are difficult to convert into cat-like voices and which cat sounds are difficult to reproduce from human input.
5. Human perceptual study: evaluate whether human listeners can distinguish real cat vocalizations from synthesized ones.

Subexperiment 5 is a human-subject study and is not a computational experiment. It should be treated as an design/analysis task only, not as an execution task in this environment.

While this project focuses on human-to-cat VC, we may also include traditional VC as a reference baseline to interpret the results. Specifically, the following conventional VC settings should be considered as comparison baselines:
- intra-gender conversion
- inter-gender conversion
- open-set and closed-set voice conversion

These baselines are not separate research tasks by themselves; they serve as reference conditions for evaluating how far the human-to-cat conversion departs from standard VC behavior. When reporting results, each subexperiment should explicitly compare its findings against at least one of these conventional VC settings and explain the relevance of the comparison.


## Working rules

- This directory is the only allowed write location for all generated files, scripts, logs, experiments, and outputs.
- Do not modify files outside this directory.
- Create one subdirectory per subexperiment using the naming rule: `<subexperiment_number in 2 digits>.<subexperiment_name>`.
- Each subexperiment directory must contain:
  - `README.md` summarizing the objective, methods, data, scripts, output files, results, and discussion
  - at least two Python scripts:
    - one script to collect or generate experiment data
    - one script to analyze the data and produce plots or quantitative results
  - generated result files such as `.png`, `.csv`, `.json`, or `.txt` outputs
- Scripts must be runnable from the project environment and should save outputs inside the same subexperiment directory unless otherwise specified.
- After running each script, verify that:
  - output files were created
  - results are internally consistent
  - plots or metrics match the stated objective
  - any inconsistencies are fixed by revising the scripts and rerunning them
- Supplemental experiments are allowed when necessary, but any additional experiments must be clearly described in the subexperiment README and justified by the research question.

## Project-specific instructions

### Environment
Use the local conda environment named `nvcnsf`. Activate it with `conda activate nvcnsf`.

Recommended toolchains:
- `JAX` ecosystem (`flax`, `orbax`, etc.) for deep learning
- `PyTorch` for dataset handling
- `librosa` for DSP and audio feature extraction
- `matplotlib` for plotting results

### Reference implementation
Refer `infer.py` at the repository root for the voice conversion pipeline.
It contains the basic usage pattern for:
- loading a checkpoint
- extracting content and speaker embeddings
- inferring fundamental frequency (F0) and aperiodic components (beta)
- decoding condition features to generate waveforms

### Pretrained model
The pretrained model is located at `/path/to/checkpoint/`.

This model is the default model for all VC experiments in this project. All inference steps should use it unless a different explicit model is specified.

It is the pitch-controllable NVCNSFV2 (load with `models.load_g_checkpoint`, `item_names=('g_model',)`): F0 is extracted from the input, mapped with speaker semitone statistics (`map_fo`), and can be shifted in semitones before decoding. The shared wrapper is `01.end_to_end_feasibility/vc.py` (`VoiceConverter.convert(x, z, z_src, semitone_shift)`). Results of the pre-V2 model are kept in `results_v1_old/` of subexperiments 01 and 03.
